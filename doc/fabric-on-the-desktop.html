✦ Fabric on the COSMIC desktop

Interactive feature map — every fabric capability, its desktop usefulness, how we envision it, and what's built. Source of truth: fabric-on-the-desktop.md. New here? See getting-started.md. Status as of 2026-05-28.

The shape: one daemon (cosmic-fabricd) owns the fabric deployment — the one channel; everything else is a thin socket client. One profile (policy.toml) every surface reads. Three UI surfaces — Loom 🧵 (Workbench: Run / Library / Models), Kit 🧰 (launcher · panel · quick-action), Session 💬 (chat) — plus the socket itself as a 4th, programmatic surface.

▾ Surfaces

🧵 Loom — Workbench

Run (source→pattern→prompt→run→send-to) · Library (curate the active set) · Models (define instantiations). The power + config surface; configures the others.

🧰 Kit — quick tie-ins

Launcher (Super→type) · panel popup (quick-run on clipboard) · quick-action (Super+Shift+F on the selection). select → inference → review → close.

💬 Session

Lightweight multi-turn chat over fabric sessions (server-side history). Lighter than a full agent; depth lives here.

🔌 Socket (4th)

cosmic-fabric.sock — line-JSON API the UIs sit on; the seam for automation / goo. Not user-facing.

▾ Appendix — goo (isolated / aspirational)

out of scope — not part of cosmic-fabric

goo is a sibling router. Two arrows, both optional:

  • goo → fabric — goo, headless, consumes the socket (4th surface) as a client: fabric/inference→run, fabric/assemble→assemble. A protocol match, no bridge.
  • fabric → goo — a "Send to goo" destination that hands the artifact to goo's UI (seeded) for interactive onward routing. The UI, not the socket; same shape as "Send to Claude Desktop". goo as a meta-destination.

Full design: cosmic-goo-integration.md. cosmic-fabric ships fully without goo.
