How this answers your six points

1 · Source in the response. Every artifact card carries a ⊹ on "…" source-reference line, and the conversation control bundles source + prompt + response into one transcript. The workspace also keeps the source pane visible above, always.

2 · Editable source, multi-origin. Both popup and workspace share one Source model: a segmented origin picker (📋 clipboard · 📂 file · T text · 🎤 audio · 🖼 image) loading into an editable field. In the popup it's a single-line field (⤢ expands to a textarea); in the workspace a full box. Clipboard is a seed, not a binding — no auto-resample per run. Live char count.

3 · Show the assembled prompt — assembly is automatic. No Assemble button: the Prompt card re-renders live as you edit source / pattern / variables (prompt-first flow). System text dimmed, your input bright. Run is the only action; the Response card is always present (placeholder until Run). After Run the prompt collapses to a one-line header you can re-expand (▸). Clicking the popup's result glance opens this workspace with the run loaded.

4 · Send-to = customizable destination registry. Compact copy-icon-with-dropdown controls — one on the prompt card, one on the response card, and the conversation one promoted to the window header bar (COSMIC's standard spot for whole-document actions). Default action is plain Copy; the ▾ opens the registry (Copy ✓, Save to file, then Claude/Alpaca shown but disabled until goo's route layer lands, then Manage destinations… → Settings). No claude:// wired ahead of its handler.

5 · A real response window. This is it — a proper libcosmic window (same mechanism as Settings: cosmic-fabric-panel window). The popup keeps notifying for the fast path; the workspace is the openable, persistent view. Broadcast results from the launcher can open/populate it.

6 · Audio (later). The 🎤 Speak seed is the only hook now. The voice→STT→meta-prompt→pattern-pick→fabric→TTS loop is its own design — this mockup just reserves the spot.

Footer carries Retry, Stats (GPU/placement/timing), Clear, Settings. Emoji are placeholders for COSMIC symbolic icons.

Polymorphic source & response (new states). URL source swaps the text field for a URL + Fetch + scrape/readability toggle, and shows the → 4,210 chars markdown transform feeding the prompt (so prompt-first still reads true). Image source shows a thumbnail (no editable text), attaches as vision input, and — the load-bearing bit — the header model badge goes active: "⚠ qwen3 can't see images · switch ▾", Run disabled until you pick a vision model. Image-gen response dispatches on type: the Response card holds an image with Save image, not a text box.

Model-by-capability — the crux you flagged. Once patterns need different model types (text/vision/image/audio) across local + several APIs, the preferred-models list can't stay flat. Settings → Models gets capability tabs (Text/Vision/Image/Audio), models grouped by vendor, capability inferred per model (vendor+family) with a manual tag override. A pattern then only offers models from the category it needs — which is what powers the workspace's "switch to a vision model" swap. This is the real complexity; how far it's worth going depends on what fabric + our models/APIs actually handle well on this box.

This is four build slices — I'd ship in this order, each usable on its own:

① Popup polish (verbs+desc, status pill, result glance, "Open workspace" button) — small, on top of today's panel.

② Workspace window (source editor, pattern, auto-assembled prompt + always-present response cards, conversation header action) — the big one.

③ Send-to registry + Settings (Copy/Save now; destination management; the disabled goo entries).

④ Audio (separate design, much later).
